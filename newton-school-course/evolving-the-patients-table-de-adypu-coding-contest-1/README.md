Three requirements come in from three different departments the same week:

 * Compliance: Every patient record must now show a blood_group, including the ones already in the table. Where it isn&#39;t known yet, the value should be "Unknown".

 * Pharmacy: A new risk_score column is being added to hold a value from 0 to 10 set by the doctor after consultation. The database itself must reject anything outside that range.

 * Billing: The finance team has revised the fee structure to allow amounts like ₹499.50 and ₹1,249.75 instead of only whole rupees. Right now those values get silently rounded off when entered, and the CFO wants this fixed before this month&#39;s billing cycle closes.

Write one script that handles all three, applied to the table as it stands &mdash; no dropping, no recreating, no existing row lost, no statement failing on the data already inside. After making the schema changes, add a new patient named Neha Reddy, phone 9911223344, age 29, consultation fee ₹550.00, with a risk_score of 7 &mdash; and end the script with a SELECT that displays every row of the updated table.

## Solution

```js
-- 1. Add the blood_group column with a default value of 'Unknown' for existing and future rows
ALTER TABLE patients ADD COLUMN blood_group VARCHAR(10) DEFAULT 'Unknown';
UPDATE patients SET blood_group = 'Unknown' WHERE blood_group IS NULL;

-- 2. Add the risk_score column with a check constraint ensuring values are between 0 and 10
ALTER TABLE patients ADD COLUMN risk_score INTEGER CHECK (risk_score >= 0 AND risk_score <= 10);

-- 3. Alter consultation_fee from INTEGER to NUMERIC(10, 2) to support decimal fee amounts
ALTER TABLE patients ALTER COLUMN consultation_fee TYPE NUMERIC(10, 2);

-- 4. Insert the new patient record for Neha Reddy
INSERT INTO patients (full_name, phone, age, consultation_fee, blood_group, risk_score)
VALUES ('Neha Reddy', '9911223344', 29, 550.00, 'Unknown', 7);

-- 5. Display every row of the updated table
SELECT * FROM patients;
```
